# Проектирование Astranaut DSL

Статус: обсуждение, не утверждённая спецификация.

## Цель

Проработать синтаксис и семантику Astranaut DSL и согласовать их с новой моделью astranaut-core. Итог — согласованная спецификация с примерами и критериями для последующей реализации.

## Исходные наблюдения — не проектные решения

Изучены README, парсер, ключевые части сопоставления и тесты astranaut, примеры uast/trastformer и документы новой модели core.

- `A <- B` объявляет узел с одним ребёнком; абстрактный тип с единственным подтипом записывается `A <- B | 0`.
- Повторяющиеся дети в объявлениях представлены отдельной формой `List <- {Item}`; смешанные схемы текущий парсер не поддерживает.
- Повторное объявление одного номера узлового захвата слева запрещено; повторные записи в захват данных конкатенируются.
- Шаблон `A` требует отсутствия детей, но в интерпретаторе не требует отсутствия данных, вопреки README.
- Теги объявляются в схемах; шаблоны и результат используют позиционные списки детей.
- В uast.dsl сохранились старые формы `$...$`, `#1...` и данные после детей.
- Разбор разделителей местами не учитывает кавычки.
- Генератор ещё зависит от старого `org.cqfn:astranaut-core:1.2.13`; новая модель core требует отдельного согласования.
