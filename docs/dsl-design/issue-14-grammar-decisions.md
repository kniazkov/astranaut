### D378. Порядок фильтра данных и проверки детей — принято 01.11.2026

Задача #14, часть Q06. Ответ автора: «Да».

В узловом шаблоне фильтр данных и проверка детей могут присутствовать одновременно. Порядок фиксирован: тип → фильтр данных → проверка детей; внешние кратность и захват as применяются к полученному шаблону по §13.1. Фильтр можно опустить, проверку детей можно опустить. D378 не решает вопрос совместного использования позиционной и именованной проверок детей (Q10).

Identifier<$text>[] проверяет тип Identifier, связывает сериализованные данные с text и требует отсутствия всех фактических детей. Его дерево разбора: NodePattern(type=Identifier, data=Capture(text), children=Positional([])). Identifier с данными "abc" без детей совпадает и связывает text="abc"; наличие ребёнка означает несовпадение. Действуют обычные статические проверки схем и захватов.

Container<"box">[Identifier] проверяет данные и весь список детей; Container<"box">(value: Identifier) проверяет данные и указанное место. В этих примерах предполагаются совместимые объявления типов с данными.

Обратный порядок Identifier[]<$text> и Container(value: Identifier)<"box"> — синтаксическая ошибка до сопоставления. Это правило относится к шаблонам; грамматика построения результата обсуждается отдельно.

Частичная продукция EBNF для шаблона с одной формой проверки детей (не полная грамматика Q06; совместная форма Q10 пока не определена):

```ebnf
typed-node-pattern = type-name, [ data-filter ], [ children-check ];
children-check = positional-children | named-children ;
```




### D379. Единственная форма списка детей — принято 01.11.2026

Задача #14, Q10. Ответ автора: «Да».

В одном узловом шаблоне или конструкторе результата разрешена только одна форма списка детей: позиционная либо именованная. Сочетание обеих форм в любом порядке — синтаксическая ошибка до сопоставления или построения результата (D379).

```text
Pair[Identifier, Number](left: Identifier) // Ошибка синтаксиса.
Pair(left: Identifier)[Identifier, Number] // Ошибка синтаксиса.
Pair(left: $a)[$a, $b]                    // Ошибка синтаксиса.
Pair[$a, $b](left: $a)                    // Ошибка синтаксиса.
```

В шаблоне совместные ограничения выражаются пересечением отдельных одноузловых шаблонов. Оба операнда проверяют один и тот же узел; действуют обычные правила пересечения. В результате выбирается одна форма задания детей, без смешивания назначений.

```text
Pair[Identifier, Number] & Pair(left: Identifier)
// Альтернативные формы результата:
Pair[$a, $b]
Pair(left: $a, right: $b)
```

Для схемы node Pair(left: Node, right: Node) пересечение совпадает с Pair, у которого left — Identifier, right — Number. Pair с переставленными детьми не совпадает. В результате при обязательных одиночных захватах a и b совместимых типов обе показанные формы строят Pair с left=$a и right=$b. Примеры предполагают объявленные Identifier и Number.
