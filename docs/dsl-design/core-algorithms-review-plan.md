# План пересмотра алгоритмов astranaut-core

Обсуждение алгоритмов вынесено отдельно по указанию автора. Сейчас завершаются контракты базовых классов в задаче #19 и PR #27. Этот план не означает согласования перечисленных открытых решений или реализации изменений.

## LabeledTreeBuilder и свойства

- [ ] Пересмотреть LabeledTreeBuilder и его приватный LabeledNode.
- [ ] Адаптировать хранение и обход детей к слотам, сохраняя пустые слоты и их порядок.
- [ ] Спроектировать обёртки узла, типа и строителя для дополнительных свойств. Обычный Node берёт свойства из типа; стандартный Builder ничего о свойствах не знает.
- [ ] Согласовать сохранение дополнительных свойств при пересоздании через тип обёртки. Сейчас LabeledNode.getType() возвращает исходный тип, а отдельных обёрток типа и строителя нет.
- [ ] Проверить структурную прозрачность, equals/hashCode и совместимость обёртки типа с фабрикой и уникальностью имён. Последний вопрос о контракте прозрачности пока не получил отдельного ответа.
- [ ] Определить семантику выбора: структурное равенство, идентичность объекта или конкретное вхождение. Сейчас selected.contains(original) зависит от реализации Set; обычный HashSet не различает структурно равные разные объекты.
- [ ] Разобрать повторное навешивание свойств, конфликты ключей, общие поддеревья и сохранение Fragment.

## Адаптация алгоритмов к новым базовым контрактам

- [ ] Проверить структурное сравнение по слотам и использование готового hashCode() за O(1), исключить повторное вычисление хэшей поддеревьев.
- [ ] Проверить обходы, поиск и замену узлов при общих поддеревьях и адресации по слотам.
- [ ] Устранить зависимости от удалённых методов Node и плоского setChildren(list).
- [ ] Отдельно пересмотреть форматирование и сериализацию с сохранением границ слотов.
- [ ] Согласовать конкретные алгоритмы и проверки отдельным обсуждением; не переносить прежние реализации автоматически.

Решения по базовым интерфейсам: [журнал задачи #19](issue-19-decisions.md).

## Хелперы диапазонов Fragment и Position

По согласованию автора методы Fragment.fromPositions(), Fragment.fromNodes() и Position.bounds() сохраняются; подробный пересмотр отложен сюда.

- [ ] Согласовать пустые входы, null, служебные позиции EmptyFragment и смешение источников.
- [ ] Различать вычисление охватывающего диапазона по неупорядоченным позициям и строгий конструктор Fragment(begin, end), который не переставляет границы.
- [ ] Согласовать обработку отсутствующего происхождения и диапазонов нулевой длины при объединении.
- [ ] Проверить канонические координаты, точное сохранение CRLF и исключающий конец диапазона.
