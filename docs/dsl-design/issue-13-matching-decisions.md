## Q01: исходные обязательные примеры

```text
Block[Statement*, Statement*]
Block[Statement*, Return, Statement*]
(Identifier+)+ as xs
```

Первый и третий шаблоны уже запрещены при компиляции. Второй уже разрешён: при Return : Statement и остальных детях Statement один Return даёт единственное распределение, два Return — неоднозначного кандидата, который отвергается. Жадность не разрешает выбирать один из двух Return.

## Ответ по Q01 — D373, 01.11.2026

Ответ автора: «Да, принимаем».

Само существование неоднозначного входа не является общим основанием для запрета шаблона. Статические запреты применяются к определённым классам: доказанно неоднозначным соседним повторениям без обязательного разделителя, неоднозначному разбиению на итерации и конфликтующим обычным захватам. Для остальных случаев неоднозначность проверяется на конкретном входе. Обязательный разделитель разрешает рассматриваемую конструкцию, но не гарантирует однозначность её совпадения и не отменяет других статических проверок.

```text
Block[Statement*, Statement*]          // Ошибка компиляции: соседние повторения.
(Identifier+)+ as xs                   // Ошибка компиляции: границы итераций.
Block[Statement*, Return, Statement*]  // Допустимый шаблон с разделителем.
```

При Return : Statement и остальных детях Statement один Return даёт единственное распределение и успешное сопоставление. Два Return дают два выбора центрального элемента: кандидат отвергается при сопоставлении до построения результата, без ошибки исполнения. Жадность не выбирает один из Return. Ноль Return означает обычное несовпадение.

Для первых двух запрещённых форм достаточно доказанного неоднозначного входа: один Statement можно отдать любому из двух повторений; два Identifier — одной или двум внешним итерациям. Наличие у этих форм других, однозначных входов запрет не снимает.

Это граница классов проверок, а не требование статически решать все возможные случаи неоднозначности. Если неоднозначность не выявлена заранее, сохраняется проверка кандидата на входе. Решения D178, D179 и D285 сохраняются.


## Ответ по Q02 — D374, 01.11.2026

Ответ автора: «Да».

Выбор разных веток альтернативы сам по себе не образует разные распределения входа. Различие границ частей или итераций образует разные распределения; одинаковый итоговый плоский захват не устраняет это различие. Согласованность обычных захватов проверяется отдельно по §11.5.

```text
(Identifier | Identifier) as x
(Identifier, Colon | Identifier, Colon) as xs
(Identifier+)+ as xs
```

В первом примере на одном Identifier есть два совпадения веток, но одно распределение: обе ветки поглощают то же вхождение, x одинаков. Шаблон допустим; неоднозначности нет.

Во втором примере на последовательности Identifier, Colon есть два совпадения веток, но одно распределение: одинаковые границы частей и тот же упорядоченный список вхождений xs. Шаблон допустим; неоднозначности нет.

В третьем примере на двух Identifier возможны одна внешняя итерация из двух элементов либо две внешние итерации по одному элементу. Это два распределения с разными границами итераций. Одинаковый список xs их не объединяет; шаблон отвергается при компиляции по D285.

Объединение совпадений одинаковых веток не отменяет проверку обычных захватов и не складывает вклады аккумуляторов разных веток. При конфликте обычных захватов сохраняются статические и динамические проверки §11.5; при согласованных захватах действует выбор вклада аккумуляторов, а не их суммирование. Уточнение порядка вложенного выбора остаётся вопросом Q03.
